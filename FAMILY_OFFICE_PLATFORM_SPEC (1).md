# McNutt Legacy — Family Office Platform Implementation Specification

**Proposed production hostname:** `legacy.mcnutt.cloud`  
**Status:** Build specification · 2026-11-21 · US federal and New Jersey first  
**Audience:** GitHub Copilot, implementation engineers, family administrators, and reviewers

## 1. Product and delivery contract

Build a private, multigenerational family office workspace. Owners should be able to answer: What do we own and owe? What did we earn this year? What should we reserve for taxes? When can each spouse retire? What would survivors and beneficiaries actually receive? Which actions are due and where is the evidence?

A workspace can contain spouses, children, future descendants, related households, businesses, estates and trusts. An individual can exist in a plan without a login. Relationships and authority change over time. The same underlying financial fact supports tax, wealth, insurance and planning views through explicit scope and derivation. Target advisor-grade workflows with measurable outcomes: every reported figure drills to source or assumption, the family can compare and reproduce alternatives, and the CPA can reconcile supported return lines without reconstructing the underlying books.

First release scope is read-only source synchronization, internal records, planning, document review, and explicitly approved exports. Trading, payments, insurer binding, e-filing, legal execution, and instructions to custodians remain outside the execution scope. Never seed actual household finances, contacts, documents or secrets into source control or test fixtures.

## 2. Architecture and conventions

Use the invoice platform as the shared-host reference. Its repository specifies Laravel 12, PHP 8.2 or newer, Apache/PHP-FPM, MySQL or MariaDB, compiled frontend assets, cron, and an idempotent deploy script. Reuse that deployment shape and the McNutt Cloud integration contracts. Verify actual installed versions and available CPU, memory and disk during host preflight. The frontend and Python runners below are new application components.

| Layer | Required implementation |
|---|---|
| Web UI | React, strict TypeScript, Vite, Tailwind CSS, accessible component primitives, React Router and TanStack Query. Laravel serves a minimal authenticated HTML shell and hashed bundles from the same origin. Lazy-load module routes and large chart components. Use typed API clients generated from OpenAPI. Keep charts paired with keyboard-accessible tables. |
| Application API | Modular Laravel backend on Apache/PHP-FPM, with Laravel 12 as the compatibility reference. Pin a supported Laravel/PHP combination based on preflight and maintenance horizon. Laravel owns auth, workspace policies, canonical writes, audit, transactional outbox and MCP. |
| Persistence | MySQL or MariaDB, DB-backed sessions, durable queues and private storage. Run integration tests against the production database engine and version family. |
| Compute and document runners | Python 3 in an application-owned per-release virtual environment. Pin the Python minor, lock dependencies and build verified wheels for the host target. Use Pydantic for boundary validation, NumPy for bounded reproducible simulations, and Decimal for authoritative monetary calculations. |
| Production runtime | Apache, PHP-FPM, database and cron invoking bounded workers. Node is a workstation and CI build dependency; deploy compiled React assets. Base deployment uses no Redis, Docker, public Python server or permanent worker daemon. |

### React application

Place the frontend in `resources/js/`, with route modules by domain, shared accessible controls, and generated contracts. Laravel handles auth, API, health and MCP routes before the authenticated browser fallback. Internal requests use host-only session cookies and CSRF protections. Keep sensitive data in scoped in-memory query caches, clear caches on scope switch/logout, and keep credentials and financial data out of persistent browser storage. Perform writes and authorization on the server. Use string decimals for money in API payloads, format in the UI, and keep tax arithmetic out of React. Provide loading, empty, stale, denied, conflict and partial-result states. Use same-origin immutable asset URLs and a restrictive CSP.

### Python runner boundary

Place runner packages in `runners/`, with `pyproject.toml`, a lockfile, typed CLI dispatch and pytest fixtures. Own deterministic tax-rule evaluation, retirement/drawdown projections and simulations in Python. Also run OCR, document normalization, reconciliation proposals and selected import transformations there. Laravel orchestrates each job and owns all published records. Keep one authoritative implementation for each calculation.

Pass a versioned JSON request to an allowlisted Python module over stdin and receive a bounded, schema-validated result over stdout. Include job ID, schema version, input manifest, engine/rule versions, seed when relevant and expected result type. Use protected per-job files for large inputs or outputs and pass only explicit job-local paths. Invoke by absolute executable path and argument array, with no shell interpolation. The Python process inherits a minimal environment, with no app or database credentials. Run sensitive parsers under an isolated job identity or sandbox without access to the rest of the vault. Keep provider credential use and external OCR calls behind the authorized application integration adapter.

Laravel claims jobs with a renewable lease, rechecks authorization, validates results and attempt ownership before idempotent commit, and schedules cleanup. Set hard time, memory, CPU/thread, file and output bounds. Distinguish failed, timed out, cancelled and retryable attempts. Reject outputs from expired attempts and invalid versions. Persist sanitized metrics and source/result manifests. A runner crash leaves financial records unchanged. Stage job schema changes so both release generations can handle queued work or drain affected queues during the update.

Use commands/application services for writes, policies for authorization, repositories/query services for scoped projections, and deterministic calculators behind typed interfaces. Domains: Identity, Household, Ledger, Integrations, Portfolio, Compensation, Real Estate, Debt, Tax, Planning, Estate, Insurance, Vault, Notifications, Reports and Operations. Publish committed events through a transactional outbox; handlers are retry-safe with stable event IDs. Co-locate records and rules in the monolith, isolate provider contracts behind adapters. Prefer indexed relational facts; JSON for versioned provider payloads and rule/extraction metadata. Use ULIDs, DB constraints, optimistic edit versions, UTC instants and local financial dates. Currency uses decimal arithmetic or integer minor units with explicit currency, rates, and rule-specific rounding. Quantities, prices, rates and FX need independent decimal scales. Use ISO 4217 where applicable. Store original FX and normalized values, source, as-of and conversion policy. Never silently convert or value missing amounts at zero.

Every root belongs to a workspace. Enforce workspace consistency with composite reference constraints or typed link tables, with tests for cross-workspace writes. Prevent double counting through canonical facts, purpose-specific source precedence and equity/asset consolidation rules. A home can appear in several modules while contributing once per applicable rollup.

### Data lifecycle and APIs

Observation states: received, quarantined, mapped, needs review, reconciled, superseded. Model facts as distinct actual, provisional, projected and override values; preserve observed/effective time and recording time. Manual overrides retain actor, rationale, source, scope and optional expiry. Reports and simulations persist frozen manifests and are re-authorized at read time. Route shape: `/w/{workspace}/...`, `/api/v1/workspaces/{workspace}/...`, `/auth/callback`, `/mcp`. Publish OpenAPI and JSON Schemas. Typical commands: import preview/commit/reverse, confirm extraction, reconcile period, run tax scenario, compare plan versions, close/restate year, request/revoke export. Heavy operations return 202 + scoped job ID. Require Idempotency-Key on API mutations, binding it to principal/scope/body, and If-Match for mutable resources; return structured errors and conflict responses. Use cursor pagination and bounded filter/date intervals; workers recheck initiator authorization for user-triggered sensitive work.

## 3. Login, delegation and household privacy

Use McNutt Cloud for authentication and local policies for authorization. The live integration guide confirms the signed callback parameters and /api/validate.php. The invoice reference documents the signed callback payload, app ID, HMAC-SHA256 raw-payload verification, expiry/replay checks, server-to-server validation and host-only cookie. Confirm live protocol, callback correlation and revalidation behavior against registered client before production. Key identity by stable issuer/principal, reject non-user browser principals, never use email to infer permissions. Reject unsigned sibling-domain identity cookies. Use `__Host-mcnutt_legacy_session`, HTTPS, CSRF, rotation, session inactivity and absolute expiry, revalidation on sensitive actions, and suppression of callback query strings/tokens in logs. Pin auth origin and callback URL, clear callback parameters immediately. Verify step-up/MFA capability with upstream; require verified fresh MFA or app WebAuthn step-up for privileged actions. Revoke active sessions and delegated API grants on material access changes.

|---|---|

| Spouse/co-owner | Joint scopes plus individually granted private records. Permit combined planning with both parties’ consent. |

| Service principal / MCP client | Dedicated named scopes, user delegation or explicitly authorized connector identity, lifecycle and revocation independent of web login. |

Apply deny-by-default policies at row, field, link, report and export level. Precedence: workspace and active membership first, explicit restrictions then specific grants. Test permissions on loaded resources, eager loads, aggregate totals, cache keys, file downloads, jobs, citations and MCP resources. Treat report and scenario access as dependent on underlying data classification. Use independent approval for emergency release and high-risk delegation where configured; record required evidence and release checklist. Give family owners an access review, audit history and recovery plan. No routine support impersonation.

## 5. Wealth, investments, compensation and liabilities

**Portfolio.** Track bank cash, money markets, CDs, T-bills, public securities, ETFs, fixed income, retirement accounts, HSAs, 529s, alternatives, private funds, business interests and digital assets. Include asset class, restrictions, beneficiary/TOD, owner, tax bucket, custodian and valuation source. Track lots and basis adjustments, reinvestment, corporate actions, commissions, capital gains, income, cash flows, commitments/capital calls, distribution sources and liquidity windows. Show concentration by issuer, sector, currency, asset class and tax bucket. Explain time-weighted and money-weighted returns separately, display coverage/stale pricing and reconcile positions to statements. Treat look-through allocations as exposures distinct from book value.

**Equity compensation.** Track employer/advisory roles and agreements, ISO/NSO, RSU/PSU, restricted stock, MIU/profits interests, ESPP and carried interests. Record grant and tranche dates, service/performance milestones, expiration, strike, FMV, units, cliff, acceleration, separation and change of control, settlement choice, currency, tax basis, withholding, lockups, 83(b) deadlines if relevant and document clauses. Separate granted, vested, exercisable, exercised, settled and forfeited. Model cash exercise, cashless/net exercise if available, sell-to-cover, expiry, exit and no-liquidity, plus payout waterfall with preferences, participation, dilution, MOIC/hurdles, debt and fees. Report optionality and value ranges with assumptions. Reconcile shares and payroll tax reporting before counting a realized event; after exercise, issued shares and exercised options cannot both contribute. Show exercise funding and immediate versus eventual tax impacts.

**Property and assets.** Track primary/second homes, rentals, vehicles, boats, jewelry, collectibles and other high-value items with title/ownership, acquisition, appraisal, location, serial IDs and evidence. For rentals retain P&L, bookings, usage log, NOI, occupancy, capex, debt service, cash-on-cash, taxable activity and disposition/recapture assumptions. Track land vs building basis, placed-in-service dates, improvements, personal conversion, class/life/method and accumulated depreciation. Valuation precedence selected separately per purpose (market, tax, replacement, estate): licensed feed or comps, appraisal, verified owner override, and supported modeled estimate. AI extracts or annotates comparables; it never invents appraisals. Save range/source/date/confidence, freshness rules, anomaly review and accepted valuation history. Track inventory images, warranties, titles, restrictions and insurance schedules.

**Debts.** Mortgages, HELOCs, auto/boat loans, cards, lines, business and intra-family notes, policy loans, guarantees and contingent commitments. Store opening/current balance, principal, accrued interest, payment allocation, APR/reset index/margin/caps, fixed/reset periods, escrow, fees, collateral, maturity, balloon, recourse, terms and penalty. Amortization uses actual due dates, supported compounding conventions and rounding; reconcile to statement, identify negative amortization. Compare payoff date, total interest, liquidity and after-tax outcomes for extra principal, refinance, accelerated, avalanche or custom schedules. Separate taxes/insurance escrow from principal; distinguish liens, guarantees and actual liabilities. Feed all strategies into planning, tax and estate.

**Year close.** Produce calendar or entity fiscal-year snapshot with income by earned/business/investment/rental category, cash flow, realized/unrealized returns, spending, savings, liabilities, tax paid/reserve/refund, year-end wealth and a selected projected wealth trajectory. Include personal and consolidated views, assumptions and source coverage. Bridge beginning → ending wealth by contributions, withdrawals, market, FX and adjustments with explicit residual. Reopening requires reason and approval; new immutable version supersedes old. Show discrepancies and actual versus projection visually and in exports.

## 6. Federal and NJ tax engine

### Contract and precision

Deterministic calculation with traceable IRS/NJ return-line parity for the declared supported cases, complete reconciled data and exact form rounding. Guarantee repeatability and testable parity, not a universal accuracy percentage for incomplete inputs or unsupported returns. Show tax liability separately from withholding, credits, estimated payments, balance due/refund and penalties. Result states: estimate (assumed/missing inputs), calculated (rules and inputs complete within scope), reconciled (source totals and line checks passed), CPA-reviewed (named sign-off on an immutable run), unsupported (blocking item, no authoritative total). Partial estimates may show a clearly labelled bound or covered subtotal. Reconciliation compares to actual signed filings without overwriting either result. Support individual or joint tax units per year, separate entity accounting, and scenarios across multiple years.

Implement versioned jurisdiction/year rule packs from actual forms, instructions and authorities. Each rule has ID, effective dates, authority URL and locator, calculation dependencies, inputs, rounding, declaration of assumptions, fixtures and reviewer. Store rule activation, immutable signed/hashed release metadata and supersession; CPAs or named reviewers approve pack release. Implement ordered calculation graph with line-level trace (source fact IDs, intermediate values, rule and reasons). Distinguish enacted, provisional and hypothetical legislation. Prior-year runs pin prior rules. Protect tax rule changes behind diff and explicit review. Never use LLM arithmetic as the authoritative calculator.

Use synthetic or adequately anonymized fixtures with independently validated expected lines. Test integer thresholds, phase-outs, rounding and statutory form line totals.

## 7. Retirement, goals and multigenerational planning

Use Monarch’s separation between near-term goals and long-range forecasting as the interaction baseline: derive a proposed spending baseline from complete months, disclose exclusions, compare recurring versus one-off cash flow, and let the user override and version assumptions. Use RightCapital’s strategy comparison and probability/confidence presentation as benchmarks. Add private equity liquidity, separate spouses, estate ownership, debt, and drill-down to reconciled tax results. The product acceptance target is broader household context and reproducible decisions, not a claim of superiority to every advisor.

- **Plan and scope.** Support individual, joint, branch and consolidated plans with consent. Each participant has independent retirement/claim age, earnings and longevity. Model minor and future descendant goals without identity records granting portal access. Branch a baseline into alternatives with changed assumptions, events and strategy deltas. Publish/view only to authorized participants. Preserve versioned templates.
- **Inputs.** Salary/bonus, equity vest/exercise and hypothetical exit, investment returns/inflation by class, rental/business cash flows, inheritances/windfalls with timing/ranges, pensions, individual SSA statement estimates and dependent/spousal/survivor benefits subject to supported rules, life insurance, debt, taxes, healthcare, ACA/Medicare transitions, IRMAA where supported, long-term care and education. Allow SS claim ages per spouse and alternative benefit assumptions. Show source date and manual benchmark if SSA import unavailable.
- **Cash-flow engine.** Monthly events for near-term liquidity, annual reporting through arbitrary horizon and configurable age of death with survivor transitions. Define precedence by event date and stable tie-breaker; baseline order is opening holdings and debt → scheduled external income/expenses/contributions/debt by date → investment return accrual → withdrawals and tax settlement to reserve floor → closing balances. Iterate withdrawal and tax interactions to a documented tolerance/limit and surface non-convergence. Distinguish pretax, Roth, taxable, HSA, education-restricted and illiquid buckets. Preserve lot/basis and realized gains where modeled. Apply dated inflation and nominal/real conversion. Transfers are neutral in consolidated cash flow. Display each plan year with starting/ending cash, assets, debts, tax, spending, benefits, withdrawals, shortfalls and legacy values.
- **Strategy tools.** Compare retirement dates, SS claiming, spending tiers and phases, sale of property/business, delayed exits, paydown vs invest, Roth conversions, RMDs, charitable distributions where supported, sequence of taxable/deferred/Roth drawdowns, simplified guardrails and minimum liquidity. Compare SEP IRA, solo 401(k), employer plans, Traditional/Roth IRA, HSA and 529 contributions using eligibility, taxpayer role, compensation, employer/employee limits, shared deferral caps, spouse coverage and relevant dates. Rank by goals such as after-tax spend, shortfall risk or estate value with change in significant assumptions surfaced.
- **Risk.** Deterministic cases (base, adverse, optimistic) plus seeded, reproducible correlated Monte Carlo or block-bootstrap provider with documented return/covariance basis, horizon, inflation model and configured path count. Store seed, generator/version and input manifest. Offer stress events for early losses, higher inflation, two years of income loss, early death, late private exit, no exit and uninsured property loss. Show percentiles, probability of covering essential spending/net liquidity, first shortfall and magnitude; define success explicitly and include sensitivity. Probability is conditional on model assumptions. Limit compute, paginate run details and give jobs cancel/retry controls.
- **Verification.** Golden amortization and zero-return projection; spouse claim-age and survivor transitions; partial-year move; minimum-distribution behavior; year-to-year bucket reconciliation; same-run seed reproducibility; household roll-up with restricted records; delayed equity exit and tax gross-up convergence. Prove plan comparisons use same baseline assumptions except the explicit differences.

## 9. Insurance

Track personal property, home/flood/auto/boat/jewelry, term/permanent life, disability, long-term care, umbrella and business policies including cyber, GL and professional liability as applicable. Model insured persons/entities/assets, owner, carrier/agent, beneficiaries, policy term, premium schedule, deductibles, attachment points, limits/sublimits, exclusions, endorsements, waiting periods, conditions, replacement vs actual cash value, carrier ratings source, claims, renewals, and evidence. Coverage can apply to many assets and include per-item schedules. Store business claims-made retroactive dates and tail information. Link each extraction to section/page evidence.

Whole life and similar contracts have separate cash surrender as-of value, outstanding loans, surrender charges/tax basis and benefit/proceeds assumptions. Net worth recognizes eligible net surrender value, and death scenarios transition to eligible net death proceeds instead of counting both. Track premium commitments and lapse/loan sensitivity. Term carries death benefit in relevant scenarios and separately tracked premiums. Flag coverage gaps, duplicate areas and risky dependencies (e.g., umbrella underlying minima). For example, a loss summary calculates estimated eligible loss, deductible, applicable sublimit, underlying limit and potential excess, with exclusions and unknown terms surfaced. Do not add overlapping policies into an unconditional total.

Insurance shopping flow: select renewal or coverage need, create baseline schedule, redact broker packet, compare quotes by normalized limits, deductibles, endorsements/exclusions, premiums, insurer and term; mark important differences and unknowns. User previews and approves recipient-specific export. Never send automatically or bind coverage by inference. Track shopping decisions, claims and deductible reserve. Alert on renewal, lapse, valuation age, beneficiary review and uncovered assets.

## 10. Vault, Document AI and ChatGPT

### Document lifecycle

Upload → staging/quarantine → type/size validation and malware scan → encrypted immutable original and hash → OCR/extract → structured review → approved records → access-controlled indexed retrieval. Support PDF/images, statements, contracts, tax forms, IDs if expressly needed, appraisals, policies and legal documents. Validate media independently of extensions, block active formats by default, cap file/page/pixel counts, and enforce rendering timeouts. Use dedicated private storage beyond web root, per-file encryption keys wrapped with an environment-specific root, separate key custody/backups, integrity checks and rotation drills. Version metadata and keep originals, derived text, page geometry, checksums, retention, legal hold, authority and access. Serve via authorized short-lived download streams, record exports/downloads, prevent shared caching, and support user-controlled purge/retention with legal holds. Encrypt high-risk structured fields such as SSNs, document identifiers and account number fragments where warranted. Prefer last four and document references.

Use deterministic PDF/text extraction first where possible and a configured OpenAI extraction adapter for hard cases. Each structured schema has version, per-field confidence, page/coordinates, source quote and validation. Keep prompt/model/run identifiers, schema versions and override lineage. Treat untrusted documents and OCR text as data; instructions in them cannot change auth, invoke tools, modify mappings, or create approvals. Reject impossible totals, duplicate documents and unit/date errors. Hand review on uncertain amounts, classifications, personally identifying data and all material writes from external chat. Minimize fields sent to provider with workspace policy, record processing consent, retention settings and authorized destinations. Provider retention and tenant settings require verification. Include local/manual path and failure queue.

### Remote MCP contract

Provide MCP over HTTPS Streamable HTTP. Implement initialization/version negotiation, resources and tools with JSON Schemas, pagination, annotations and scoped errors. ## 12. Shared host deployment, backups and operations

Repo must include `deploy.sh`, `scripts/update.sh`, `scripts/rollback.sh`, preflight, backup and restore/verify commands, examples for Apache/PHP-FPM, application health checks and operator runbooks. Follow invoice repo's single-command, repeatable, scoped deployment convention. Improve isolation: unique Unix runtime user and FPM pool/socket, unique DB schema and least-privilege app/migration accounts, dedicated deployment identity, release dirs and app-scoped read-only repo credential. Runtime never reads the deployment credential or writes code. No dependency on shared web process identity or other app credentials. App paths default to `/opt/mcnutt-legacy/releases`, `/opt/mcnutt-legacy/current` symlink, `/etc/mcnutt-legacy`, `/var/lib/mcnutt-legacy`, `/var/log/mcnutt-legacy`. Root-owned configs and correct service-user reads. Persist storage across releases. No secrets in git, arguments, URLs, stdout or artifacts.

1. **Preflight:** SSH verified host key, deploy identity/sudo scope, host OS, PHP extensions and FPM version, supported Python minor and venv support, compatible wheels, parser isolation, Apache modules, supported DB, disk, memory, DNS/A/AAAA, TLS/ACME, cron, file permissions, cross-app isolation, repo access, SSO registration and secrets. Refuse unsafe collisions; host package/system changes require explicit operator intent. Produce redacted plan with `--dry-run`.
2. **Bootstrap:** scoped vhost, FPM, cron/logrotate, DB, TLS, private directories and backups. Use config syntax tests before graceful reload; revert changed app-owned files on error. Never rewrite existing app vhosts/pools or global PHP defaults. Initially use staging with separate origin, secrets, test data and no live connectors.
3. **Update:** lock deployment, retrieve tested pinned commit or signed/checksummed artifact, validate runtime, wheel hashes and lockfiles, install a release-local Python venv from the verified wheelhouse, verify Vite manifest and asset hashes, run Python self-check and build cache for release, verify current encrypted backup and point-in-time recovery options, run expand/contract compatible migrations, warm assets and run release health/smoke, atomically flip symlink, reload if needed, prune after retention. If deploy fails, revert symlink/config and check prior release. No automatic destructive down migrations. Data restore is an incident action with DB/blob alignment and write pause approval. Cron and release activation coordinate schema/job compatibility.
4. **Cron:** stagger minute ticks with bounded runtime and nonoverlap, per-workspace job limits and exponential backoff. Use the scheduler to invoke bounded Laravel queue workers by priority, separating payroll and interactive tasks from OCR, connector sync and Monte Carlo. Subprocess time limits must fit within worker and lease limits. Cap compute concurrency and BLAS threads across the host and validate resource ceilings under concurrent sibling-app traffic. Monitor failed jobs, stale links/connectors and job age. No standing worker required. Verify concurrent deploy/runs and interrupted recovery.
5. **Backups:** default target RPO 24 hours, RTO 4 hours, confirm host/offsite performance in rehearsal. Encrypt DB and vault offsite with independently held keys, manifest with hashes and consistent version/watermark, periodic restore to isolated sandbox, compare totals and decrypt fixtures. Track last successful run, key rotation and documented recovery when shared host is unavailable.
6. **Production acceptance:** confirm DNS/TLS, app callback and actual principal, masked health and no public secrets/uploads, authenticated user workflows, connector paths, OTP/step-up, notification delivery semantics, restricted tenant access, backup restore, rollback and sibling-app checks. Record deployed SHA, migrations, health and open issues. Deployment occurs after implementation and host access handoff through a secure channel.

SLO targets for staging under agreed test load: p95 authenticated read under 500 ms for typical dashboards with warmed summary views and no provider call, mobile LCP under 2.5 s under agreed network profile, jobs visible within one cron cycle, import 10k rows resumably without request timeout. Document load shape and measure. Use data-classification-based logs with correlation IDs, status and duration, health and retention policy. Include on-call runbook for revoked integration, stale rules, bad import, compromised session, provider outage, failed restore and queue saturation.
